# M8 Fotos – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein Foto pro Aktivität aus Galerie oder Kamera, verkleinert auf höchstens 512 Pixel, gespeichert in der Datenbank, sichtbar wie die Aktivität in Details, Verlauf und auf der Karte.

**Architecture:** Das Backend speichert das JPEG in der neuen Tabelle `activity_photos` und die Versionsnummer in `activities.photo_version` (aus der Sequenz `photo_versions`). `PUT`, `GET` und `DELETE` unter `/activities/{id}/photo` laufen in den bestehenden Routen, Service und Repository der Aktivitäten, die Sichtbarkeit nutzt die vorhandene Bedingung `visibleTo`. Die App verkleinert das Foto hinter dem Interface `PhotoPreparer`, lädt es nach dem Speichern der Aktivität hoch und zeigt Bilder mit Coil über den gemeinsamen OkHttp-Client.

**Tech Stack:** Ktor 3.6, Exposed 1.6, Flyway, PostgreSQL, javax.imageio (nur Kopf lesen), Jetpack Compose, Retrofit, Coil 3.3.0, androidx.exifinterface 1.4.2, Photo Picker und `TakePicture`.

**Spec:** `docs/superpowers/specs/2026-11-18-fotos-design.md`

## Entscheidungen, die über die Spec hinausgehen

- **Größe zuerst am Header prüfen:** Die Route lehnt anhand von `Content-Length` vor dem Lesen ab und liest danach höchstens `204_800 + 1` Byte (`receiveChannel().readBuffer(...)`). Kein neues Ktor-Plugin.
- **JPEG-Prüfung ohne Entpacken:** `PhotoRules.validate` prüft die Kennung `FF D8 FF` am Anfang und `FF D9` am Ende und liest Breite und Höhe mit dem JPEG-Reader von ImageIO über `MemoryCacheImageInputStream`, ohne das Bild zu dekodieren. Die Prüfung des Endes fängt abgebrochene Uploads ab, die bei Ktor wie ein vollständiger Body ankommen. Jede Exception beim Lesen des Kopfs heißt „kein JPEG“, auch die `CMMException` mancher Farbprofile.
- **Nummer aus der Sequenz:** `savePhoto` schreibt Bild und neue `photo_version` in einer Transaktion. Entfernen löscht die Zeile in `activity_photos` und setzt `photo_version` auf `NULL`.
- **Antworten:** `PUT` liefert 200 mit der aktualisierten `ActivityDto`, `DELETE` liefert 204 auch ohne Foto, `GET` liefert die Bytes mit `Content-Type: image/jpeg` und `Cache-Control: private, max-age=31536000, immutable`.
- **App ohne Android im Test:** ViewModels kennen nur `PhotoPreparer` (Quelle als `String`, Ergebnis als `File`). Die Android-Umsetzung `AndroidPhotoPreparer` dekodiert ab Android 9 mit `ImageDecoder`, darunter mit `BitmapFactory` und `ExifInterface`. Getestet werden die reinen Größenfunktionen, die Datenschicht gegen MockWebServer und die ViewModels, nicht `AndroidPhotoPreparer`, `PhotoPickers` und die Screens.
- **Dateien:** Kamera-Aufnahmen landen in `cacheDir/camera/` und werden nach dem Verkleinern gelöscht. Fertige JPEGs liegen bis zum Hochladen in `filesDir/photos/`. In Task 5 und 6 löscht die App die Datei nach jedem Versuch, sie hochzuladen, auch wenn er scheitert; scheitert schon das Anlegen der Aktivität, bleibt das Foto im Formular. Die Gesamtprüfung hat das als Verlust von Kamera-Fotos eingestuft. Die Nachbesserung (`docs/superpowers/plans/2026-11-25-m8-nachbesserung.md`) setzt deshalb den Wortlaut der Spec um („bis zum erfolgreichen Hochladen“): Fotos liegen in `noBackupFilesDir/photos/`, nach Netz- und Serverfehlern wartet das Foto auf „Foto erneut hochladen“ in den Details, Abmelden und „Verwerfen“ räumen auf. Task 8 beschreibt diesen Stand.
- **Formular übersteht das Beenden:** `RecordViewModel` sichert Sportart, Datum, Uhrzeit, Dauer, Ort, Beschreibung, Sichtbarkeit, die Herkunft aus dem Timer und den Pfad des Fotos in `SavedStateHandle`. Nicht hochgeladene Fotos bleiben nach „← Zurück“ oder „Verwerfen“ in `filesDir/photos/` liegen; ein Aufräumen in `onCleared` würde das Foto eines gesicherten Formulars löschen. Seit der Nachbesserung löscht „Verwerfen“ das Foto, und Abmelden leert den Ordner. Während des Speicherns steht kein Formular im Handle, damit nach einem im Hintergrund beendeten Speichern kein schon gespeichertes Formular zurückkommt.
- **Gemeinsamer OkHttp-Client:** `AppContainer` baut ihn einmal für Retrofit und Coil. `TouchGrassApp` stellt Coil den `ImageLoader` bereit. Wechselt `AuthSession.state` zu `AuthState.LoggedOut`, leert der Container Speicher- und Datei-Cache von Coil. Die Nachbesserung gibt Coil eine Kopie mit eigenem `Dispatcher` (Interceptoren und Verbindungen bleiben gemeinsam), fängt Fehler beim Leeren ab und löscht beim Abmelden auch die Fotodateien.
- **Anzeige:** Verlauf 56 dp quadratisch beschnitten, Karte und Details in voller Breite im Seitenverhältnis 4:3 mit `ContentScale.Fit`.

```kotlin
package de.touchgrass.activities

import de.touchgrass.jpeg
import de.touchgrass.plugins.ApiException
import java.awt.color.ColorSpace
import java.awt.color.ICC_Profile
import java.awt.image.BufferedImage
import java.io.ByteArrayOutputStream
import javax.imageio.ImageIO
import kotlin.test.Test
import kotlin.test.assertEquals
import kotlin.test.assertFailsWith
import kotlin.test.assertTrue

class PhotoRulesTest {
    private fun failure(bytes: ByteArray): List<String?> =
        assertFailsWith<ApiException> { PhotoRules.validate(bytes) }.let { listOf(it.field, it.message) }

    private fun png(): ByteArray {
        val out = ByteArrayOutputStream()
        ImageIO.write(BufferedImage(4, 3, BufferedImage.TYPE_INT_RGB), "png", out)
        return out.toByteArray()
    }

    // Mit dem PYCC-Profil der JDK im Kopf wirft der JPEG-Reader eine CMMException, weil LCMS das Profil nicht wieder als Bytes ausgeben kann.
    private fun jpegWithPyccProfile(): ByteArray {
        val chunks = ICC_Profile.getInstance(ColorSpace.CS_PYCC).data.toList().chunked(65_000)
        val segments = chunks.mapIndexed { index, chunk ->
            val length = 16 + chunk.size
            byteArrayOf(0xFF.toByte(), 0xE2.toByte(), (length shr 8).toByte(), length.toByte()) +
                "ICC_PROFILE".encodeToByteArray() + byteArrayOf(0, (index + 1).toByte(), chunks.size.toByte()) + chunk.toByteArray()
        }
        val image = jpeg()
        return segments.fold(image.copyOfRange(0, 2)) { start, segment -> start + segment } + image.copyOfRange(2, image.size)
    }

    @Test
    fun `JPEG bis 512 Pixel an der längsten Seite ist gültig`() {
        PhotoRules.validate(jpeg())
        PhotoRules.validate(jpeg(512, 384))
        PhotoRules.validate(jpeg(384, 512))
    }

    @Test
    fun `längste Seite über 512 Pixel wird abgelehnt`() {
        val tooLong = listOf("photo", "Das Foto darf höchstens 512 Pixel lang sein.")
        assertEquals(tooLong, failure(jpeg(513, 384)))
        assertEquals(tooLong, failure(jpeg(10, 600)))
    }

    @Test
    fun `andere Formate und kaputte JPEGs werden abgelehnt`() {
        val notJpeg = listOf("photo", "Bitte ein Foto im JPEG-Format schicken.")
        val brokenJpeg = byteArrayOf(0xFF.toByte(), 0xD8.toByte(), 0xFF.toByte()) + "kein Bild".encodeToByteArray() + byteArrayOf(0xFF.toByte(), 0xD9.toByte())
        assertEquals(notJpeg, failure(ByteArray(0)))
        assertEquals(notJpeg, failure(png()))
        assertEquals(notJpeg, failure(brokenJpeg))
        assertEquals(notJpeg, failure(jpeg().let { it.copyOf(it.size - 2) }))
        val unusualProfile = runCatching { PhotoRules.validate(jpegWithPyccProfile()) }.exceptionOrNull()
        assertTrue(unusualProfile == null || unusualProfile is ApiException, "unerwartete Exception: $unusualProfile")
    }
}
```
`brokenJpeg` beginnt mit `FF D8 FF` und endet mit `FF D9`, dazwischen steht Unsinn. So besteht er beide Prüfungen der Kennung, und erst der JPEG-Reader wirft eine `IIOException`. Dem gekürzten `jpeg()` fehlen nur die letzten zwei Byte `FF D9`: Sein Kopf ist vollständig, der JPEG-Reader liest Breite und Höhe ohne Fehler, erst die Prüfung des Endes lehnt es ab. Das JPEG mit dem PYCC-Profil (rund 235 KB) ruft `validate` direkt auf, über HTTP käme es nur bis zur 413. Die letzte Prüfung erlaubt bewusst auch „gültig“, damit der Test nicht an einem späteren Fix in LCMS scheitert. Ohne den breiten `catch` in Step 5 ist sie rot.

package de.touchgrass.activities

import de.touchgrass.plugins.ApiException
import de.touchgrass.plugins.validationError
import io.ktor.http.HttpStatusCode
import javax.imageio.ImageIO
import javax.imageio.stream.MemoryCacheImageInputStream

object PhotoRules {
    const val MAX_BYTES: Int = 204_800
    const val MAX_SIDE: Int = 512

    private val JPEG_START = listOf(0xFF, 0xD8, 0xFF).map { it.toByte() }
    private val JPEG_END = listOf(0xFF, 0xD9).map { it.toByte() }

    fun tooLarge(): Nothing =
        throw ApiException(HttpStatusCode.PayloadTooLarge, "PAYLOAD_TOO_LARGE", "Das Foto ist zu groß.", "photo")

    // Bricht das Hochladen mittendrin ab, kommt der Body bei Ktor wie ein vollständiger an. Ohne FF D9 am Ende fehlt ein Teil des Bildes.
    fun validate(jpeg: ByteArray) {
        if (jpeg.take(JPEG_START.size) != JPEG_START || jpeg.takeLast(JPEG_END.size) != JPEG_END) notJpeg()
        val (width, height) = headerSize(jpeg) ?: notJpeg()
        if (maxOf(width, height) > MAX_SIDE) validationError("photo", "Das Foto darf höchstens 512 Pixel lang sein.")
    }

    // Liest Breite und Höhe nur aus dem Kopf. ImageIO.read würde das Bild entpacken, und ein kleines JPEG mit riesigen Pixelangaben könnte den Speicher sprengen.
    // Jede Exception heißt „kein JPEG“: Bei manchen Farbprofilen (ICC) wirft der Reader statt einer IIOException eine CMMException.
    private fun headerSize(jpeg: ByteArray): Pair<Int, Int>? {
        val readers = ImageIO.getImageReadersByFormatName("jpeg")
        if (!readers.hasNext()) return null
        val reader = readers.next()
        return try {
            MemoryCacheImageInputStream(jpeg.inputStream()).use { input ->
                reader.setInput(input, true, true)
                reader.getWidth(0) to reader.getHeight(0)
            }
        } catch (e: Exception) {
            null
        } finally {
            reader.dispose()
        }
    }

    private fun notJpeg(): Nothing = validationError("photo", "Bitte ein Foto im JPEG-Format schicken.")
}
```
`MemoryCacheImageInputStream` legt keine Cache-Datei auf der Platte an. Fehlt der JPEG-Reader oder scheitert das Lesen des Kopfs mit einer Exception, gilt das Foto als kein JPEG. Außer der `IIOException` für kaputte Daten wirft der Reader bei ungewöhnlichen ICC-Profilen eine `CMMException`, unter älteren JDK-21-Versionen auch eine `IllegalArgumentException`. Ohne den breiten `catch` würden daraus 500. Die Prüfung auf `FF D9` am Ende braucht es, weil Ktor bei einem abgebrochenen Hochladen die bis dahin empfangenen Byte wie einen vollständigen Body liefert; ohne sie würde ein halbes Foto gespeichert. Die App schreibt das Ergebnis von `Bitmap.compress` unverändert, und das endet immer auf `FF D9`.

package de.touchgrass.ui.photo

import kotlin.math.roundToInt

const val MAX_PHOTO_BYTES = 204_800

val JPEG_QUALITIES = listOf(85, 75, 65, 55, 45)

data class PhotoSize(val width: Int, val height: Int)

fun fitWithin(width: Int, height: Int, maxSide: Int = 512): PhotoSize {
    val longest = maxOf(width, height)
    if (longest <= maxSide) return PhotoSize(width, height)
    val scale = maxSide.toDouble() / longest
    return PhotoSize((width * scale).roundToInt().coerceAtLeast(1), (height * scale).roundToInt().coerceAtLeast(1))
}

fun sampleSizeFor(width: Int, height: Int, target: Int = 512): Int {
    val longest = maxOf(width, height)
    var sampleSize = 1
    while (longest / (sampleSize * 2) >= target) sampleSize *= 2
    return sampleSize
}
```

```kotlin
package de.touchgrass.ui.photo

import android.content.Context
import android.graphics.Bitmap
import android.graphics.BitmapFactory
import android.graphics.Canvas
import android.graphics.Color
import android.graphics.ImageDecoder
import android.graphics.Matrix
import android.net.Uri
import android.os.Build
import androidx.annotation.RequiresApi
import androidx.core.graphics.createBitmap
import androidx.core.net.toUri
import androidx.exifinterface.media.ExifInterface
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.withContext
import java.io.ByteArrayOutputStream
import java.io.File
import java.io.FileNotFoundException
import java.io.InputStream
import java.util.UUID

class AndroidPhotoPreparer(private val context: Context) : PhotoPreparer {
    override suspend fun prepare(source: String): File = withContext(Dispatchers.IO) {
        val uri = source.toUri()
        try {
            val jpeg = decode(uri).withoutGainmap().onWhite().toJpeg()
            val dir = File(context.filesDir, "photos").apply { mkdirs() }
            File(dir, "${UUID.randomUUID()}.jpg").apply { writeBytes(jpeg) }
        } catch (e: Exception) {
            throw PhotoException(UNSUPPORTED_PHOTO)
        } finally {
            if (uri.authority == PHOTO_AUTHORITY) context.contentResolver.delete(uri, null, null)
        }
    }

    // ImageDecoder dreht schon nach der EXIF-Angabe, BitmapFactory nicht. Nur der Weg unter Android 9 dreht deshalb selbst.
    private fun decode(uri: Uri): Bitmap =
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.P) decodeWithImageDecoder(uri) else decodeWithBitmapFactory(uri)

    @RequiresApi(Build.VERSION_CODES.P)
    private fun decodeWithImageDecoder(uri: Uri): Bitmap =
        ImageDecoder.decodeBitmap(ImageDecoder.createSource(context.contentResolver, uri)) { decoder, info, _ ->
            val size = fitWithin(info.size.width, info.size.height)
            decoder.setTargetSize(size.width, size.height)
            decoder.allocator = ImageDecoder.ALLOCATOR_SOFTWARE
        }

    private fun decodeWithBitmapFactory(uri: Uri): Bitmap {
        val bounds = BitmapFactory.Options().apply { inJustDecodeBounds = true }
        open(uri).use { BitmapFactory.decodeStream(it, null, bounds) }
        val options = BitmapFactory.Options().apply { inSampleSize = sampleSizeFor(bounds.outWidth, bounds.outHeight) }
        val sampled = open(uri).use { BitmapFactory.decodeStream(it, null, options) } ?: throw PhotoException(UNSUPPORTED_PHOTO)
        val exif = open(uri).use { ExifInterface(it) }
        val target = fitWithin(sampled.width, sampled.height)
        val matrix = Matrix().apply {
            postScale(target.width.toFloat() / sampled.width, target.height.toFloat() / sampled.height)
            if (exif.isFlipped) postScale(-1f, 1f)
            postRotate(exif.rotationDegrees.toFloat())
        }
        return Bitmap.createBitmap(sampled, 0, 0, sampled.width, sampled.height, matrix, true)
    }

    private fun open(uri: Uri): InputStream =
        context.contentResolver.openInputStream(uri) ?: throw FileNotFoundException(uri.toString())

    private fun Bitmap.withoutGainmap(): Bitmap {
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.UPSIDE_DOWN_CAKE && hasGainmap()) gainmap = null
        return this
    }

    private fun Bitmap.onWhite(): Bitmap {
        if (!hasAlpha()) return this
        val opaque = createBitmap(width, height)
        Canvas(opaque).apply {
            drawColor(Color.WHITE)
            drawBitmap(this@onWhite, 0f, 0f, null)
        }
        return opaque
    }

    private fun Bitmap.toJpeg(): ByteArray {
        var jpeg = ByteArray(0)
        for (quality in JPEG_QUALITIES) {
            jpeg = ByteArrayOutputStream().also { compress(Bitmap.CompressFormat.JPEG, quality, it) }.toByteArray()
            if (jpeg.size <= MAX_PHOTO_BYTES) break
        }
        return jpeg
    }
}
```
Ablauf: Ab Android 9 dekodiert `ImageDecoder` direkt in der Zielgröße und als Software-Bitmap, dreht dabei schon nach EXIF. Unter Android 9 liest `BitmapFactory` zuerst nur die Größe, dekodiert dann mit `inSampleSize` (längste Seite bleibt mindestens 512) und dreht und skaliert in einem Schritt über eine `Matrix` nach `ExifInterface`. Ab Android 14 fällt der Ultra-HDR-Anteil weg, Transparenz kommt auf Weiß. `Bitmap.compress` schreibt kein EXIF, also auch keinen Aufnahmeort. Das JPEG wird mit den Qualitäten aus `JPEG_QUALITIES` gespeichert, bis es höchstens `MAX_PHOTO_BYTES` groß ist. HEIC unter Android 8 (`BitmapFactory` liefert `null`) und jeder andere Fehler beim Lesen, Dekodieren oder Schreiben (auch `ImageDecoder.DecodeException` und `SecurityException`) werden `PhotoException(UNSUPPORTED_PHOTO)`. Im `try` steht kein Suspend-Aufruf, `catch (e: Exception)` fängt also keine Abbrüche der Coroutine ab.

package de.touchgrass.ui.photo

import android.content.ActivityNotFoundException
import androidx.activity.compose.rememberLauncherForActivityResult
import androidx.activity.result.PickVisualMediaRequest
import androidx.activity.result.contract.ActivityResultContracts.PickVisualMedia
import androidx.activity.result.contract.ActivityResultContracts.TakePicture
import androidx.compose.runtime.Composable
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.saveable.rememberSaveable
import androidx.compose.runtime.setValue
import androidx.compose.ui.platform.LocalContext
import androidx.core.content.FileProvider
import androidx.core.net.toUri
import java.io.File
import java.util.UUID

class PhotoPickers(val openGallery: () -> Unit, val openCamera: () -> Unit)

// Oben im Screen aufrufen, nie in Dialogen oder Bottom Sheets: Beendet Android die App, während Kamera oder Fotoauswahl
// offen sind, kommt das Ergebnis nur dort wieder an. Deshalb steht auch die Kamera-Uri schon vor dem Start in rememberSaveable.
@Composable
fun rememberPhotoPickers(onPicked: (String) -> Unit, onError: (String) -> Unit): PhotoPickers {
    val context = LocalContext.current
    var pendingCapture by rememberSaveable { mutableStateOf<String?>(null) }
    val gallery = rememberLauncherForActivityResult(PickVisualMedia()) { uri ->
        if (uri != null) onPicked(uri.toString())
    }
    val camera = rememberLauncherForActivityResult(TakePicture()) { saved ->
        val capture = pendingCapture
        pendingCapture = null
        if (capture != null) {
            if (saved) onPicked(capture) else context.contentResolver.delete(capture.toUri(), null, null)
        }
    }
    return PhotoPickers(
        openGallery = { gallery.launch(PickVisualMediaRequest(PickVisualMedia.ImageOnly)) },
        openCamera = {
            val dir = File(context.cacheDir, "camera").apply { mkdirs() }
            val uri = FileProvider.getUriForFile(context, PHOTO_AUTHORITY, File(dir, "${UUID.randomUUID()}.jpg"))
            pendingCapture = uri.toString()
            try {
                camera.launch(uri)
            } catch (e: ActivityNotFoundException) {
                pendingCapture = null
                onError("Keine Kamera-App gefunden.")
            }
        },
    )
}
```
Die Kamera-Datei endet auf `.jpg`, weil `ImageDecoder` Inhalte von `content://`-Adressen nur als `image/*` öffnet und der FileProvider den Typ aus der Endung ableitet. Bricht man die Aufnahme ab, löscht der Callback die Datei; nach einer Aufnahme löscht sie `AndroidPhotoPreparer`. Galerie-Adressen werden nie gelöscht.

private const val KEY_SPORT = "sportCode"
private const val KEY_DATE = "date"
private const val KEY_TIME = "time"
private const val KEY_DURATION = "duration"
private const val KEY_LATITUDE = "latitude"
private const val KEY_LONGITUDE = "longitude"
private const val KEY_DESCRIPTION = "description"

data class RecordUiState(
    val sports: List<SportDto> = emptyList(),
    val sportsError: String? = null,
    val sportCode: String? = null,
    val date: LocalDate,
    val time: LocalTime,
    val duration: String = "",
    val location: GeoPoint? = null,
    val description: String = "",
    val visibility: Visibility = Visibility.PRIVATE,
    val photoPath: String? = null,
    val photoBusy: Boolean = false,
    val fromTimer: Boolean = false,
    val saving: Boolean = false,
    val fieldErrors: Map<String, String> = emptyMap(),
    val error: String? = null,
    val savedMessage: String? = null,
    val newAchievements: List<AchievementDto> = emptyList(),
    val discarded: Boolean = false,
)

class RecordViewModel(
    private val api: SportApi,
    private val timerStore: TimerStore,
    fromTimer: Boolean,
    private val photos: PhotoPreparer,
    private val savedState: SavedStateHandle,
    private val clock: Clock = Clock.systemDefaultZone(),
) : ViewModel() {
    private val _state = MutableStateFlow(emptyForm())
    val state: StateFlow<RecordUiState> = _state.asStateFlow()

    init {
        val saved = savedForm()
        if (saved != null) {
            _state.value = saved
        } else if (fromTimer) {
            viewModelScope.launch { timerStore.state.first()?.let(::fillFromTimer) }
        }
        loadSports()
        viewModelScope.launch { _state.collect { keepForm(it) } }
    }

    fun loadSports() {
        viewModelScope.launch {
            try {
                val sports = apiCall { api.sports() }
                _state.update { it.copy(sports = sports, sportsError = null) }
            } catch (e: ApiException) {
                _state.update { it.copy(sportsError = e.message) }
            }
        }
    }

    fun onSportChange(code: String) = edit("sportCode") { copy(sportCode = code) }

    fun onDateChange(date: LocalDate) = edit("startedAt") { copy(date = date) }

    fun onTimeChange(time: LocalTime) = edit("startedAt") { copy(time = time) }

    fun onDurationChange(value: String) = edit("durationMin") { copy(duration = value) }

    fun onLocationChange(location: GeoPoint?) = edit("latitude", "longitude") { copy(location = location) }

    fun onDescriptionChange(value: String) = edit("description") { copy(description = value) }

    fun onVisibilityChange(value: Visibility) = edit("visibility") { copy(visibility = value) }

    fun onPhotoPicked(source: String) {
        edit("photo") { copy(photoBusy = true) }
        viewModelScope.launch {
            try {
                val file = photos.prepare(source)
                _state.update { it.copy(photoPath = file.path, photoBusy = false) }
            } catch (e: PhotoException) {
                _state.update { it.copy(photoBusy = false) }
                showFieldError("photo", e.message ?: UNSUPPORTED_PHOTO)
            }
        }
    }

    fun onPhotoError(message: String) = showFieldError("photo", message)

    fun removePhoto() {
        _state.value.photoPath?.let { File(it).delete() }
        edit("photo") { copy(photoPath = null) }
    }

    fun save() {
        val current = _state.value
        if (current.saving || current.photoBusy) return
        val sportCode = current.sportCode ?: return showFieldError("sportCode", "Bitte eine Sportart wählen.")
        val duration = current.duration.trim().toIntOrNull()
            ?: return showFieldError("durationMin", "Bitte die Dauer in ganzen Minuten angeben.")
        val request = CreateActivityRequest(
            sportCode = sportCode,
            startedAt = ZonedDateTime.of(current.date, current.time, clock.zone)
                .toOffsetDateTime()
                .format(DateTimeFormatter.ISO_OFFSET_DATE_TIME),
            durationMin = duration,
            latitude = current.location?.latitude,
            longitude = current.location?.longitude,
            description = current.description.trim().ifEmpty { null },
            visibility = current.visibility,
        )
        _state.update { it.copy(saving = true, fieldErrors = emptyMap(), error = null, savedMessage = null) }
        viewModelScope.launch {
            try {
                val response = apiCall { api.createActivity(request) }
                if (current.fromTimer) timerStore.clear()
                val photoUploaded = current.photoPath == null || tryUploadPhoto(response.activity.id, File(current.photoPath))
                val points = response.pointsBreakdown
                _state.value = emptyForm().copy(
                    sports = current.sports,
                    savedMessage = if (photoUploaded) {
                        "Gespeichert! ~${response.activity.caloriesKcal} kcal · +${points.total} Punkte (${points.describe()})"
                    } else {
                        PHOTO_UPLOAD_FAILED
                    },
                    newAchievements = response.newAchievements,
                )
            } catch (e: ApiException) {
                _state.update { it.copy(saving = false) }
                if (e.field != null) showFieldError(e.field, e.message) else _state.update { it.copy(error = e.message) }
            }
        }
    }

    fun onAchievementsSeen() = _state.update { it.copy(newAchievements = emptyList()) }

    fun discard() {
        viewModelScope.launch {
            timerStore.clear()
            _state.update { it.copy(discarded = true) }
        }
    }

    private suspend fun tryUploadPhoto(activityId: Long, file: File): Boolean =
        try {
            apiCall { api.uploadPhotoFile(activityId, file) }
            true
        } catch (e: ApiException) {
            false
        } finally {
            file.delete()
        }

    private fun fillFromTimer(timer: TimerState) {
        val start = LocalDateTime.ofInstant(timer.startedAt, clock.zone).truncatedTo(ChronoUnit.MINUTES)
        _state.update {
            it.copy(
                sportCode = timer.sportCode,
                date = start.toLocalDate(),
                time = start.toLocalTime(),
                duration = timer.durationMinutes(clock.instant()).toString(),
                fromTimer = true,
            )
        }
    }

    private fun emptyForm(): RecordUiState {
        val now = LocalDateTime.now(clock).truncatedTo(ChronoUnit.MINUTES)
        return RecordUiState(date = now.toLocalDate(), time = now.toLocalTime())
    }

    // Während des Speicherns steht kein Formular im Handle. Endet das Speichern im Hintergrund und beendet Android danach die App, käme sonst das schon gespeicherte Formular samt gelöschtem Foto zurück.
    private fun keepForm(form: RecordUiState) {
        if (form.saving) {
            savedState.remove<String>(KEY_DATE)
            return
        }
        savedState[KEY_SPORT] = form.sportCode
        savedState[KEY_DATE] = form.date.toString()
        savedState[KEY_TIME] = form.time.toString()
        savedState[KEY_DURATION] = form.duration
        savedState[KEY_LATITUDE] = form.location?.latitude
        savedState[KEY_LONGITUDE] = form.location?.longitude
        savedState[KEY_DESCRIPTION] = form.description
        savedState[KEY_VISIBILITY] = form.visibility.name
        savedState[KEY_PHOTO] = form.photoPath
        savedState[KEY_FROM_TIMER] = form.fromTimer
    }

    // Im Handle stehen auch die Argumente der Route. Ein gesichertes Formular erkennt man deshalb erst am Datum.
    private fun savedForm(): RecordUiState? {
        val date = savedState.get<String>(KEY_DATE) ?: return null
        val time = savedState.get<String>(KEY_TIME) ?: return null
        val latitude = savedState.get<Double>(KEY_LATITUDE)
        val longitude = savedState.get<Double>(KEY_LONGITUDE)
        return RecordUiState(
            sportCode = savedState.get<String>(KEY_SPORT),
            date = LocalDate.parse(date),
            time = LocalTime.parse(time),
            duration = savedState.get<String>(KEY_DURATION).orEmpty(),
            location = if (latitude != null && longitude != null) GeoPoint(latitude, longitude) else null,
            description = savedState.get<String>(KEY_DESCRIPTION).orEmpty(),
            visibility = savedState.get<String>(KEY_VISIBILITY)?.let(Visibility::valueOf) ?: Visibility.PRIVATE,
            photoPath = savedState.get<String>(KEY_PHOTO),
            fromTimer = savedState.get<Boolean>(KEY_FROM_TIMER) == true,
        )
    }

    private fun edit(vararg fields: String, change: RecordUiState.() -> RecordUiState) =
        _state.update { it.change().copy(fieldErrors = it.fieldErrors - fields.toSet(), error = null, savedMessage = null) }

    private fun showFieldError(field: String, message: String) =
        _state.update { it.copy(fieldErrors = it.fieldErrors + (field to message)) }
}

package de.touchgrass.ui.activities

import androidx.lifecycle.ViewModel
import androidx.lifecycle.viewModelScope
import de.touchgrass.data.ApiException
import de.touchgrass.data.SportApi
import de.touchgrass.data.apiCall
import de.touchgrass.data.dto.ActivityDto
import de.touchgrass.data.dto.SportDto

import de.touchgrass.ui.UiState
import de.touchgrass.ui.photo.PhotoException
import de.touchgrass.ui.photo.PhotoPreparer
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.flow.update
import kotlinx.coroutines.launch

data class ActivityDetailUiState(
    val sports: List<SportDto> = emptyList(),
    val activity: UiState<ActivityDto> = UiState.Loading,
    val photoBusy: Boolean = false,
    val deleted: Boolean = false,
    val error: String? = null,
)

class ActivityDetailViewModel(
    private val api: SportApi,
    private val id: Long,
    private val photos: PhotoPreparer,
) : ViewModel() {
    private val _state = MutableStateFlow(ActivityDetailUiState())
    val state: StateFlow<ActivityDetailUiState> = _state.asStateFlow()

    init {
        load()
    }

    fun load() {
        _state.update { it.copy(activity = UiState.Loading) }
        viewModelScope.launch {
            try {
                val sports = apiCall { api.sports() }
                val activity = apiCall { api.activity(id) }
                _state.update { it.copy(sports = sports, activity = UiState.Content(activity)) }
            } catch (e: ApiException) {
                _state.update { it.copy(activity = UiState.Error(e.message)) }
            }
        }
    }

    fun delete() {
        viewModelScope.launch {
            try {
                apiCall { api.deleteActivity(id) }
                _state.update { it.copy(deleted = true) }
            } catch (e: ApiException) {
                _state.update { it.copy(error = e.message) }
            }
        }
    }

    fun onPhotoPicked(source: String) = changePhoto {
        val file = photos.prepare(source)
        try {
            apiCall { api.uploadPhotoFile(id, file) }
        } finally {
            file.delete()
        }
    }

    fun onPhotoError(message: String) = _state.update { it.copy(error = message) }

    fun removePhoto() {
        val current = _state.value.activity
        if (current !is UiState.Content) return
        changePhoto {
            apiCall { api.deletePhoto(id) }
            current.data.copy(photoVersion = null)
        }
    }

    private fun changePhoto(change: suspend () -> ActivityDto) {
        _state.update { it.copy(photoBusy = true, error = null) }
        viewModelScope.launch {
            try {
                val activity = change()
                _state.update { it.copy(activity = UiState.Content(activity), photoBusy = false) }
            } catch (e: PhotoException) {
                _state.update { it.copy(photoBusy = false, error = e.message) }
            } catch (e: ApiException) {
                _state.update { it.copy(photoBusy = false, error = e.message) }
            }
        }
    }
}

- Ein Foto pro Aktivität. „🖼️ Galerie“ öffnet die Fotoauswahl von Android, „📷 Kamera“ die Kamera-App. Die Kamera schreibt in eine Datei im Cache der App, die ein eigener `FileProvider` freigibt.
- Die App verkleinert das Foto im Hintergrund auf höchstens 512 Pixel an der längsten Seite, ohne kleinere Fotos zu vergrößern, dreht es nach seiner EXIF-Angabe und rechnet seine Farben nach sRGB um. Sie speichert es als JPEG mit Qualität 85. Ist es dann größer als 200 KB, speichert sie es mit stärkerer Kompression erneut. Dabei fallen alle Zusatzdaten weg, auch der Aufnahmeort, ab Android 14 auch der Ultra-HDR-Anteil. Transparente Bilder bekommen einen weißen Hintergrund.
- Bilder, die das Handy nicht lesen kann (zum Beispiel HEIC unter Android 8), meldet die App mit „Dieses Bildformat wird nicht unterstützt.“ Dasselbe gilt, wenn sich ein Foto nicht als JPEG mit höchstens 200 KB speichern lässt.
- Das fertige JPEG liegt bis zum erfolgreichen Hochladen in einem Ordner der App, der nicht in die Datensicherung von Android geht. Scheitert das Hochladen an Netz oder Server oder bricht es ab, wartet es dort unter der Nummer seiner Aktivität, bis man es in den Details mit „Foto erneut hochladen“ noch einmal schickt. Lehnt der Server es ab, löscht die App es.

Abmelden leert den Bildzwischenspeicher und löscht alle Fotos der App auf dem Handy, egal ob von Hand, durch Konto löschen oder durch ein 401.

Run (PowerShell, Wurzelordner):
```powershell
$results = foreach ($dir in 'backend\build\test-results\test', 'app\build\test-results\testDebugUnitTest') {
    foreach ($file in Get-ChildItem $dir -Filter 'TEST-*.xml') {
        $suite = ([xml](Get-Content $file.FullName -Raw -Encoding UTF8)).DocumentElement
        foreach ($case in $suite.SelectNodes('testcase')) {
            $class = $case.GetAttribute('classname')
            $key = if ($dir -like 'backend*') {
                if ($class -like 'de.touchgrass.logic.*') { 'B-Rechen' }
                elseif ($class -like '*ValidationTest' -or $class -like '*.PhotoRulesTest') { 'B-Pruef' }
                elseif ($class -match '^de\.touchgrass\.(auth|config|db)\.' -or $case.GetAttribute('name') -like 'Flyway legt alle Sportarten an*') { 'B-Konfig' }
                else { 'B-API' }
            } elseif ($class -like '*ViewModelTest') { 'A-VM' }
            elseif ($class -like 'de.touchgrass.data.*' -and $class -ne 'de.touchgrass.data.TimerStateTest') { 'A-Daten' }
            else { 'A-Regeln' }
            [pscustomobject]@{ Key = $key; Failed = $null -ne $case.SelectSingleNode('failure|error'); Time = $suite.GetAttribute('timestamp') }
        }
    }
}
$results | Group-Object Key | Sort-Object Name | Format-Table Name, Count -AutoSize
$results | Group-Object { $_.Key.Substring(0, 1) } | ForEach-Object {
    '{0}-Summe {1}, fehlgeschlagen {2}, letzter Lauf {3}' -f $_.Name, $_.Count, @($_.Group | Where-Object Failed).Count, ($_.Group.Time | Sort-Object)[-1]
}
```
